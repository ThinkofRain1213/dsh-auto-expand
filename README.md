# dsh-auto-expand

DSH 插件：让**正在进行的**工作过程默认可见。

> 目标版本 DSH `0.2.1`（`engines.dsh` 限定在 `0.2.1.x`）。
> 插件通过**原地包裹**官方渲染组件工作，不重新注册任何 slot；
> 所有包裹失败都会静默降级为官方行为，绝不让 DSH 崩溃。

## 解决什么问题

DSH 默认把工作过程折叠成三层：

1. 整轮折叠（Turn 级别）
2. 操作组折叠（process group，只剩标题）
3. 思考折叠（只剩首行预览）

运行时看不到助手在做什么。本插件让**当前正在运行的那一轮**自动展开操作组、
思考内容与工具结果，并在该组工作结束后自动收起；**历史轮次完全保持官方行为**。

## 行为

| 维度 | 行为 |
|---|---|
| 结构 | 保留操作组标题与 400px 高度上限 |
| 操作组 | 当前运行 Turn 内默认展开 |
| 操作组折叠 | group 关闭（中间回复或新工具边界）时折叠一次 |
| 思考过程 | 默认展开（仅当前 Turn、仅所属操作组展开时） |
| 思考折叠 | **可配置**，默认「下一批操作出现时」 |
| **工具结果** | 当前运行的操作组内默认展开 |
| 工具折叠 | **可配置**，默认「下一批操作出现时」 |
| 历史轮次 | 完全不动，遵从官方（含「手动展开历史操作组时内层行保持折叠」） |

所有自动展开都是**一次性的**：用户手动开合之后，插件不再干预。

### 术语

| 词 | 指什么 |
|---|---|
| **本条** | 当前这一行（一段思考 / 一条工具调用） |
| **操作** | 操作组里的一个条目，对应一次工具调用或一次模型输出 |
| **批次** | 一次模型输出派发的全部操作 |
| **操作组** | 当前轮里连续的一段工作过程（process group） |

「节点 / node」是实现层叫法，不出现在界面文案里——它在中文语境里同时指 DOM
节点、AST 节点，读者无从分辨。

### 四个收起时机

按**收起由早到晚**排列（也是展开范围由窄到宽）。思考与工具**共用同一套**：

| 时机 | 含义 | 判据 | 范围 |
|---|---|---|---|
| 本条完成时 | 这一行自己的工作做完就收（思考写完 / 工具返回结果） | `done` | 本条 |
| **下一条操作出现时** | 保持展开，直到组内出现**下一条已经开始执行的操作** | 自己是**最新一条已开始**的操作 | **永远单条** |
| **下一批操作出现时**（默认） | 保持展开，直到组内出现**下一批操作**（下一次模型输出） | `step`（模型输出轮次） | 同批多条 |
| 随操作组收起 | 保持展开，直到所属操作组结束 | 恒真 | 全部 |

**「下一条操作出现时」的完整过程**（一批串行 3 条命令 A→B→C）：

| 时刻 | A | B | C |
|---|---|---|---|
| 三条参数都在流式（未开始执行） | 不展开 | 不展开 | 不展开 |
| A 开始执行 | **展开** | 不展开 | 不展开 |
| A 完成、B 未开始 | **保持展开** | 不展开 | 不展开 |
| B 开始执行 | **收起** | **展开** | 不展开 |
| B 完成、C 未开始 | 收起 | **保持展开** | 不展开 |
| C 开始执行 | 收起 | **收起** | **展开** |
| 全部完成 | 收起 | 收起 | **保持展开** |
| 下一次模型输出出现 | 收起 | 收起 | 收起 |

注意最后两行：全部完成时**只有最后一条**保持展开，不会再整批弹开一次；下一次
模型输出出现时也**只收一次**。

**为什么必须区分「已开始」**：工具节点在**参数流式阶段**就已经创建（此时 `phase`
是 `preparing`），节点序号也在这个时刻定死。若把未执行的也算作「已出现」，一批
三条工具会在执行前就分出胜负——最后一条永远最大，其余几条永远不展开。所以操作
判据只统计**已开始**（走出 `preparing`）的成员，最新者才会随执行推进而前移。

**「下一条操作」与「下一批操作」的差别**：

| 场景 | 下一条操作出现时 | 下一批操作出现时 |
|---|---|---|
| 同一批串行 A→B→C | 逐条交替：A 亮→A 收 B 亮→B 收 C 亮 | 三条**一起**展开，直到下一批出现 |
| 同一批真并发（如多个 `read`） | 同时开始 → 一起展开（先完成的被后开始的取代） | 三条**一起**展开，直到下一批出现 |

## 设置

「侧栏 → 插件 → dsh-auto-expand」详情页里有**六行**设置（改后立即生效，跨重启保留），
前五行按「操作组 / 思考 / 工具」三组排列，第六行是独立的一层：

| 行 | 控件 | 关掉/作用 |
|---|---|---|
| 自动展开操作组 | 开关 | process group body 回到官方默认折叠行为 |
| 自动展开思考过程 | 开关 | 思考块回到官方默认折叠行为 |
| 思考收起时机 | 下拉 | 四选一（见上表） |
| 自动展开工具结果 | 开关 | 工具结果回到官方默认折叠行为 |
| 工具收起时机 | 下拉 | 四选一（与思考**完全相同**的四项） |
| 隐藏查看按钮 | 下拉 | 三选一：不隐藏（默认）/ 仅当前轮 / 全部轮次 |

**门控有两层**：

1. 思考与工具都渲染在操作组 body 内部，操作组折叠时不可见 →
   关掉「自动展开操作组」后，**后五行全部变灰**；
2. 没有自动展开就没有「什么时候收起」→ 某层开关关闭时，它自己的**时机行**
   也变灰，并点名控制者。

变灰的控件保留原来的值，重新打开上层后原样恢复。

五个开关全部关掉 = 完全等于未安装本插件。

### 隐藏查看按钮

官方工具行悬停时会出现一个「查看」按钮，点它跳转到该次调用的轨迹记录。
这个按钮只在官方设置「显示代码工作视图」打开时才有入口。

本插件可以把**按钮连同它占用的那一行**一起去掉：

| 档位 | 行为 |
|---|---|
| 不隐藏（默认） | 官方行为，逐字不变 |
| 仅当前轮 | 只隐藏正在运行那一轮里的按钮；历史轮次保持官方行为 |
| 全部轮次 | 所有轮次都不显示 |

去掉的是**整个入口**，不是只把按钮变透明——官方那个按钮平时 `opacity: 0`，
但仍然占着一行高度，所以只藏视觉会留下一条空行。插件在包裹层把
`inspectCall` 置空，官方的三个按钮、详情卡给按钮让位的 88px 内边距、
以及那一行高度会一起消失。

> **一个已知的取舍**：选「仅当前轮」时，轮次**刚结束**那一刻按钮会重新
> 出现——这与「操作组自动展开」的行为完全同构（轮次结束后交回官方）。

## 唯一已知的语义边界

若**一个模型输出轮次里出现多段思考**（`reasoning → text → reasoning`），它们属于
同一个 `assistant-step` 节点、共享同一个 `anchorSeq`，所以「下一条操作出现时」
判据**无法把这几段思考区分开**——它们同进同退。

这不是缺陷：它们本来就在同一个节点里，节点级判据区分不了它们。为「看起来更合理」
而额外加约束，只会让判据与真实结构脱节。

## 已知限制

**自动收起会连带卸载行内的浮层。** 例如 `read_image` 的缩略图点开大图后，
若那一行此刻被自动收起，大图会跟着消失——因为收起时不渲染行内容，
浮层组件的内部状态也随之销毁。

官方手动收起时同样会如此，但那是你主动点的；自动收起让它变成"看着看着被收走"。
修它需要跨包读取附件组件的内部状态，代价与收益不匹配，故记录为此。

## 实现方式

**不重新注册任何 slot**，而是原地包裹三个已注册的渲染组件：

- `conversation.chat.flow` → `AutoFlow`（官方 `ChatFlow` 的克隆，只换两个 seat 组件）
- `conversation.chat.node` 的 `assistant-step` → `AutoAssistantNodeView`
- `conversation.chat.node` 的 `tool-call` → `AutoToolCallTree`（**包裹**官方 `ToolCallTree`，
  只覆盖它从 props 接收的 `useDisclosure`；官方 toolview 分派与 `GenericToolCard`
  fallback 原样保留，**不克隆 `ui-tool` 的任何代码**）

原因见 [spec/DESIGN.md](spec/DESIGN.md) 第 4 节。所有包裹失败都**静默降级**为官方行为。

## 开发

```bash
pnpm install
pnpm verify         # typecheck + build + test + smoke
pnpm pack:check     # 发布产物自检（files 覆盖、exports 可解析、产物体积）
pnpm drift          # DSH 升级后检查克隆组件是否与上游偏离
pnpm watch          # 增量构建
```

`pnpm drift` 需要一个上游源码 checkout（默认找同级的 `../deepseek-harness`，
也可以用 `--upstream <path>` 或环境变量 `DSH_SOURCE_CHECKOUT` 指定）。
没有源码 checkout 时它会跳过并以退出码 2 结束。

## 上游依赖与漂移

本插件克隆了官方的 23 个源文件（清单见 `scripts/upstream-manifest.mjs`），
因为官方没有导出这些组件、且重新注册 slot 会被拒绝（见 `spec/DESIGN.md`）。
工具结果那一层**没有新增克隆**：它是包裹官方组件、只替换一个 prop 实现的。

DSH 升级后**第一件事**是跑 `pnpm drift`：

- 它把每个克隆文件指回上游出处，用内容哈希判断上游是否变了；
- `verbatim`（整份克隆）变了 → 必须逐行重新对照，可能漏掉了新分支；
- `partial`（部分摘取）变了 → 复核被摘取的片段即可。

确认克隆已对齐后，用 `pnpm drift:record` 刷新 `spec/upstream.json`。
